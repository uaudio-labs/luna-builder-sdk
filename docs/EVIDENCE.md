# Engine behaviour: measured facts

Numbered facts about how the UANet engines behave. Code comments cite them as
"fact N"; `Luna.MockEngine` reproduces them; the live lane re-verifies them.

Status meanings:
- **verified**: seen in engine source, protocol docs, or a wire capture.
- **production**: not in the docs, but LUNA's own GUI or the shipping LUNA SDK
  relies on it, so it holds for the LUNA versions they ship with.
- **unverified**: reasoned or borrowed; needs a live check before code depends on it.
- **verified elsewhere**: measured against a live LUNA by a sibling client (the source
  names which, and on which build), but not yet re-measured by this SDK's own live lane.
  Stronger than *unverified*, weaker than *verified*; the open checks below list what to
  re-measure.

| 85 | A write is undoable only inside a touch. A bare `set` of a control's `normalized_value` changes the value but leaves the undo queue alone (`undo_uid` unchanged), on a mixer gain and on a plugin parameter alike; the same write between `set_touch {touch: true}` and `{touch: false}` makes one entry named after the control (`Volume Change`, `Dry/Wet Mix Change`), and `undo` restores the value. | 86 | Plugin slots. `set_inserts` answers `null` whether or not the plugin exists. | 88 | Track input monitoring is two properties. `input_monitor` is the writable boolean switch (not a mode string); `input_monitor_state` is read-only and says whether the input is monitored now: the switch, or an armed track while stopped or punched in (with console monitoring, an armed track always). | 89 | LUNA's Return To Zero is a GUI command, not an engine one: rack command `return_to_zero` (no session command exists). | 90 | Moving the play start. Stopped, a `play_start` write moves `location` to it, and the writer receives that `location` push (it is derived; fact 6).
